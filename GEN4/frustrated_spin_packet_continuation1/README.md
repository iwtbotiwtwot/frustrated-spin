# Consecutive packet-family continuation1

Sean Brady is originator and conceptual director. OpenAI ChatGPT and Codex are AI research collaborators.

Owner-directed continuation starts at N121 and advances through every integer in three explicit source families: packet, signed packet, and connected signed packet chain. Each source preserves the corresponding N120 graph as its induced prefix, extends the same fifteen-vertex motif used at N300, and retains ordered ports [0,1,60,61]. These source definitions are separate from the historical frustrated-source canonical atlas.

Every source receives a saved precommit before execution. Three warm exact global calculations use the inherited packet compiler and certified boundary-equality reduction where applicable. Every full scalar density and ordered conditional coefficient is compared against a separately executed full-graph variable-elimination calculation. Configuration count, first and second moments, source binding, full edge partition, and ordered ports are checked. Exact local tables can be reused; full global answer lookup never replaces a new calculation. N300 is labeled a structural replay when reached.

The three CPU worker processes each perform a serial FLINT calculation and retain native MATTER_SEARCH DomainSession receipts. This CPU backend has its own identity; no cooperative-14 timing comparison is assumed. Planning, local-table preparation, warm solves, independent verification, receipt/storage overhead, and per-worker RSS remain distinguishable.

The initial production window is eight hours. There is no scientific target endpoint: advance sequentially until the deadline, an exact verification failure, the resource gate, or an owner stop. The engineering source admission ceiling is 100000 vertices, full-graph VE has a 180-second budget, and each worker has an allocation-derived address-space limit no larger than 8 GiB. Existing GEN4 resource discovery accounts for CPU cgroups and allocated RAM. Reserve 200 GiB of container disk and never request new hardware or terminate the pod automatically. Capacity stops preserve all completed work and their actual reason; they are not mathematical failures.

All source graphs, full exact answers, comparisons, and native receipts live on the 4 TB container disk under /opt/gen4-spin-continuation1/project. The shared volume receives only compact status, metadata, and the catalog, with at most a one-minute lag during activity and a final shutdown update. Container results must be exported before the pod/container is deleted; the compact volume mirror is not a full-results backup.

Qualification replays N120 in all three families, compares retained full answers, checks N300 graph construction against the sealed source, and rejects an undeclared cross edge. A bounded N121/N122 production cycle then tests checkpoint recovery. The eight-hour launch resumes at the next uncompleted N. SIGTERM or a STOP file prevents further admission and allows the current bounded batch to finish.

Monitor: cat /opt/gen4-spin-continuation1/project/STATUS.json

Progress: tail -f /opt/gen4-spin-continuation1/project/RUN.log

Stop safely: touch /opt/gen4-spin-continuation1/project/STOP

Resume after an intentional stop: remove only that STOP file and run the same controller in a new explicit window. Completed N/family results are checksum-verified and skipped on recovery. Historical result files and global selectors are unchanged.
