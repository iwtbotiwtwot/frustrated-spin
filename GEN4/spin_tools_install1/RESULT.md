| `GEN3_SPIN_READOUT` | Condition available boundary rows and compute exact moments or rationally weighted responses |

Fresh solves accept explicit integer fields and pair couplings, a source family
and requested ports. The canonical energy convention is
`E = -sum(J_uv*s_u*s_v) - sum(h_u*s_u)`, with spins −1/+1.
The exact methods return the full density of states, ground sector and
requested conditional rows, with source identity and execution provenance.

The signed-factor operation is broader than spin. It computes finite sums of
products of declared signed tables, supports nonbinary domains and can leave
chosen variables open. The same mathematical interface is available to the
active CE consumers. Source mapping supplies the meaning of those tables.

## 6. Useful connections across the program

**Conditional response is the strongest reusable object.** A scalar spectrum
sums over boundary states; retained conditional rows preserve how the interior
responds to each boundary assignment. Volume II component composition, finite
Volume I response models and directional comparisons can all benefit from
retaining the channels their next question will need.

**Signed finite-factor contraction is the direct computational connection to
RH and other finite arithmetic work.** It preserves cancellation and open
variables while eliminating internal states. A branch can supply its own
finite expression and use the shared exact machinery; the synthetic adoption
calls establish that this path is callable.

**Graph structure is a better execution guide than N alone.** N100/N105 are
fast because their components are small. Connected graphs can also be tractable
when polynomial elimination keeps intermediate tables small. Frustrated
frontier sources can use the modular GPU route. GEN3/4 now have these choices
in one interface.

**A concrete next reuse operation follows from the saved boundary rows.** If a
new term depends only on retained boundary state b, then its energy shift
ΔE(b) gives `D_new(E') = sum_b D_b(E' - ΔE(b))`. This is a proposed extension
identified during installation; the general boundary-update operation has not
been implemented or newly tested here. It provides a precise route from
completed conditional operators to fresh related questions.

## 8. How to use it

From the project root on the workstation, or `/opt/gen4/current` on the pod:

```sh
./spin-tools sources
./spin-tools source --N 120
./spin-tools source --N 105
./spin-tools select --N 105
./spin-tools solve --N 105
./spin-tools solve graph.json --payload options.json
./spin-tools readout '{"N":120,"moment_orders":[0,1,2]}'
./spin-tools contract factors.json
```

For the historical ring:

```sh
./spin-tools source --N 120 --family SLCX028_N120_REPEATED_MOTIF_RING_V1
```

Use `source` to retrieve a completed answer, `select` to inspect a plan, and
`solve` for fresh arithmetic. `--output FILE` saves full JSON; `--full` also
prints it. Every call records its actual native session. Local calculation
commands use the shared resource controller. The installed
[guide](../../CURRENT_REVISION/engines/SLC/SPIN_TOOLS.md) documents payloads,
ports, limits, conditioning, recovery and explicit learned-policy selection.
