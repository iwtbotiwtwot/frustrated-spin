# Outcome-driven frustrated-spin follow-up

Owner Sean Brady approved a broader learning session and explicit follow-up on
its own results. This additive successor preserves the original campaign and
its original eight-hour deadline (2026-09-26 14:12:11UTC /09:12Chicago).
No hosted calls, subagents, services, hardware lifecycle actions or N>=121 solves.

The controller's experiment graph is explicit: each descendant precommit records
parent_question, the observed reason for asking it, input hashes, exact contract,
cost estimate and resource gate. Measurements update subsequent cost estimates.
Questions are deduplicated by scientific content rather than wording or parent.

- Near ties/noise generate additional alternating-order measurements, up to three
  refinement stages, with arithmetic time separate from setup/verification.
- Packet comparisons generate field and retained-port ablations. Warm cache reuse
  and cold recomputation are recorded separately.
- Successful bridge controls generate stronger bridge controls, up to seven.
- Novel width/work outcomes generate further same-N rewiring; three duplicate
  structural fingerprints stop a branch. Seed index capped128.
- A cheap new structural regime generates a full exact comparison when admitted.
- Failed exact routes generate structural diagnosis, not repeated identical work.
- Exact sign-bijection certificates get an independent inverse-coefficient check.

No claim of exhausting every possible spin graph: bounded deep exploration uses
information per cost and may stop on deadline, resource gates or recorded search
saturation. A nonempty list of five scientific next questions is always retained,
even when a computational branch saturates.

Native methods are project-scoped prototypes: exact local component-table caching
and one/two-spin conditioned component decomposition. All separator assignments
are summed. Mathematically identical component keys can reuse exact tables; timing
correlations alone never authorize skipping work. Completed new variants compare
full scalar/port densities with an independent exact route. Requested subsets of
canonical retained ports are compared against exact marginalization, not relabeled
as the original four-port observable.

STATUS.json, QUESTION_LEDGER.jsonl, FRONTIER.json, METHOD_SCORECARD.csv, SUMMARY.md,
RULE_CANDIDATES.jsonl, CERTIFICATES.jsonl and NEXT_QUESTIONS.json are updated after
every experiment. Each native experiment has its own retained session/checkpoint.
The same exclusive controller/resource lock prevents overlap with the first run.

Monitor STATUS.json. Stop with `kill -TERM PID` from that status, or create STOP
in this directory. Restart controller.py with the same project Python; completed
IDs remain skipped. No external network needed while running.
